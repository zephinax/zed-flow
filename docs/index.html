Universal Status Protocol

Teach your scripts to communicate state

ZedFlow introduces a dead-simple status protocol. Any script can report its ongoing state using stdout directives or standard LSB exit codes without any SDK dependencies.

Active / Success

Exit code 0, or print anywhere in stdout:

echo "[zedflow:status=active]"
Clear / Inactive

Exit code 2 or 3 (LSB off), or directive:

echo "[zedflow:status=clear]"
Failed / Error

Any non-zero exit code (except 2/3), or directive:

echo "[zedflow:status=failed]"

Frequently Asked Questions

Got questions? We've got answers.

Where does ZedFlow appear after launching?
ZedFlow runs as a native macOS accessory menu bar item (with a terminal >_ icon) in the top-right menu bar. It does not occupy a slot in the macOS Dock or App Switcher, keeping your workspace distraction-free.
How does ZedFlow load environment variables and paths like Homebrew or nvm?
ZedFlow executes an interactive login shell probe in the background upon launch to extract your exact user environment ($PATH, pyenv, nvm, cargo, rbenv, Homebrew). Your scripts execute with the exact same binary paths and environment variables as your terminal.
Can AI coding agents (Claude Code, Cursor, Codex) configure scripts in ZedFlow?
Yes! The zedflow CLI provides full discovery and manipulation with a dedicated --json flag across all commands (e.g. zedflow list --json, zedflow add ..., zedflow run ...). AI agents can programmatically register, inspect, trigger, and verify automation without touching the UI.
What happens if a script spawns child background processes and I click Stop?
ZedFlow implements a robust process-tree termination engine using macOS proc_listchildpids. It recursively discovers all descendant child PIDs, issues SIGKILL to the process group and all sub-processes, and frees all file descriptor handles to ensure zero runaway background processes.
